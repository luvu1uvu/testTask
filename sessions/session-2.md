## Размышления

Вопросы задавались по одному, в порядке, где каждый следующий зависел
от ответа на предыдущий, а не по заранее заготовленному списку:

1. **Стек.** SPEC.md сознательно не фиксирует стек («точный стек и команда
   запуска фиксируются отдельно в AGENTS.md»), поэтому это был первый
   вопрос. Пользователь выбрал чистые HTML/CSS/JS без сборки и без npm —
   причины сформулировал сам (минимум зависимостей, задание требует
   обходиться без них, localStorage и браузерных API достаточно). Перед
   тем как принять предложенную пользователем команду запуска
   (`python3 -m http.server 8765`), проверил в Bash, что `python3`
   действительно есть в этом окружении (3.9.6, `/usr/bin/python3`) —
   не стал фиксировать команду со слов не глядя.

2. **Тесты.** Раз npm и Node исключены из стека, обычные тест-фреймворки
   (Jest/Vitest) не подключить стандартным способом — указал это
   пользователю явно, прежде чем спрашивать про альтернативу. Заодно
   проверил `node --version` в Bash: команда не найдена. Это подтвердило,
   что вариант «гонять тесты через `node file.js`» в этом окружении в
   принципе недоступен, и укрепило выбор пользователя — HTML-страница
   с ручным раннером, открываемая тем же локальным сервером, что и само
   приложение.

3. **Линтер.** По той же причине (нет npm) обычный ESLint/Prettier
   недоступен без интернета при каждом запуске (npx). Предложил
   пользователю выбор между «без линтера» и «npx без package.json» —
   выбрано первое как более последовательное с целью «минимум
   зависимостей».

4. **Запреты, стоп-условия, финальные проверки.** По каждому пункту
   предложил пользователю набор опций на основе прочитанной SPEC.md и
   общих рисков задачи (git, зависимости, файлы вне проекта), с
   multiSelect — пользователь выбрал почти все опции и дописал
   существенно больше своих: сохранность наивного прогона и доказательств
   проверки, запрет менять формулу/статусы/формат данных без вопроса,
   запрет сетевых запросов, противоречия между SPEC/AGENTS/README,
   расхождение шага с планом и т. д. Это ощутимо детальнее черновика — не
   стал сокращать формулировки пользователя, перенёс дословно.

5. **Соглашения проекта.** Здесь агент столкнулся с внутренним
   противоречием в собственном же ответе пользователя: развёрнутый
   текст говорил «имена в коде — по-английски» и «ES-модули через
   `type="module"`», а выбранные чекбоксы (артефакт multiSelect-формы)
   говорили «весь код на русском» и «через обычные `<script>` теги без
   модулей». Не стал молча брать один вариант — переспросил оба
   противоречия отдельными вопросами. Пользователь подтвердил вариант из
   развёрнутого текста в обоих случаях (английские идентификаторы +
   русские комментарии/UI; ES-модули). Это тот случай неоднозначности
   задания/ответа, который правила курса прямо просят фиксировать.

**Допущение, принятое самостоятельно, без отдельного вопроса:** запрет
«не удалять и не перезаписывать `sessions/*.md` задним числом» не
распространил на `STATE.md` — по правилам курса (раздел 2 AGENTS.md,
Часть I) `STATE.md` прямо описан как файл, который «перезаписывается» в
конце каждой сессии. Явно оговорил это исключение в тексте запрета,
чтобы оно не потерялось.

**Что не делал по прямому указанию пользователя:** не начинал реализацию
продукта и не запускал наивный прогон — оба пункта явно исключены из
объёма этой сессии в исходном промпте.
